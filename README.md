# D&D Combat Tracker

## Описание проекта

**D&D Combat Tracker** — REST API для управления игровыми сражениями в настольной ролевой игре Dungeons & Dragons.

Приложение предназначено для упрощения работы мастера игры: позволяет создавать сражения, добавлять персонажей и монстров, рассчитывать инициативу, отслеживать ход боя и сохранять историю игровых событий.

## Основные возможности

- Создание и просмотр сражений.
- Добавление персонажей и монстров из заранее созданных шаблонов.
- Ручное добавление участников сражения.
- Удаление участников из сражения без удаления исходных шаблонов.
- Расчёт инициативы с использованием броска d20 и модификаторов.
- Автоматический бросок инициативы для NPC и монстров.
- Передача результатов бросков игроков через API.
- Разрешение ничьих в инициативе с помощью повторных бросков.
- Отслеживание порядка ходов и активного участника.
- Управление статусом сражения.
- Экспорт информации о сражении и истории событий в JSON.

## Требования для запуска

Перед запуском необходимо установить:

- Python 3.10 или выше
- PostgreSQL.

## Установка и запуск

### 1. Клонирование репозитория

```bash
git clone <ссылка-на-репозиторий>
cd dd
```

### 2. Создание виртуального окружения

Windows:

```powershell
python -m venv .venv
.venv\Scripts\activate
```

Linux / macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4. Создание базы данных

В PostgreSQL необходимо создать базу данных для приложения.
```bash
CREATE DATABASE dnd_combat;
```


### 5. Настройка переменных окружения

В корне проекта необходимо создать файл `.env` и указать параметры подключения к PostgreSQL.

Пример:

```env
DATABASE_URL=postgresql+asyncpg://postgres:password@localhost:5432/dnd_combat
```

Вместо `postgres`, `password` и `dnd_combat` необходимо указать собственные имя пользователя, пароль и название базы данных.


### 6. Применить миграции

```bash
alembic upgrade head
```

### 7. Запуск приложения

Из корневой директории проекта выполните:

```bash
uvicorn app.main:app --reload
```

После успешного запуска API будет доступно по адресу:

```text
http://127.0.0.1:8000
```

## Документация API

FastAPI автоматически генерирует интерактивную документацию.

После запуска приложения доступны:

- **Swagger UI:** http://127.0.0.1:8000/docs
- **ReDoc:** http://127.0.0.1:8000/redoc

С помощью Swagger UI можно просматривать доступные эндпоинты, отправлять HTTP-запросы и проверять ответы API.

## Основные группы эндпоинтов

### Сражения (Encounters)

| Метод | Endpoint | Назначение |
|---|---|---|
| POST | `/api/v1/encounters/` | Создание сражения |
| GET | `/api/v1/encounters/` | Получение списка сражений |
| GET | `/api/v1/encounters/{id}` | Получение информации о сражении |
| POST | `/api/v1/encounters/{id}/combatants` | Ручное добавление участника |
| POST | `/api/v1/encounters/{id}/combatants/character` | Добавление персонажа |
| POST | `/api/v1/encounters/{id}/combatants/monster` | Добавление монстра |
| DELETE | `/api/v1/encounters/{id}/combatants/{combatant_id}` | Удаление участника |
| PATCH | `/api/v1/encounters/{id}/status` | Изменение статуса сражения |
| GET | `/api/v1/encounters/{id}/export` | Экспорт сражения в JSON |

### Персонажи (Characters)

Управление созданными персонажами: создание, получение списка, просмотр отдельного персонажа и удаление.

### Монстры (Monsters)

Управление шаблонами монстров: создание, получение списка, просмотр отдельного шаблона и удаление.

*Дополнительные эндпоинты инициативы и управления ходами описаны в Swagger UI.*

## Особенности работы с инициативой

Для определения порядка ходов используется бросок двадцатигранной кости (d20).

Итоговая инициатива рассчитывается как сумма результата броска и модификатора инициативы участника.

- Для персонажей игроков результат броска передаётся мастером через API.
- Для NPC и монстров результат броска генерируется сервером.
- Участники сортируются по убыванию итоговой инициативы.
- При совпадении результатов выполняются повторные броски только среди участников с неразрешённой ничьей.
- Результаты первоначальных бросков сохраняются отдельно от результатов повторных бросков.

## Экспорт данных

Приложение поддерживает экспорт сражения и истории игровых событий в формате JSON.

Экспорт включает информацию о сражении, его участниках и зарегистрированных событиях.
